# 规则压缩、事实信息与可计算性

本项目把“识别结构，使一类问题可求解”作为研究方向，但分别验收信息是否充分、规则是否可执行且终止、有限搜索是否完整，以及成本是否可承受。统一规则可以替代逐题答案表；程序、参数、输入、实验记录和工作状态中的必要信息仍然需要载体。

## 无限题库的地址与答案来源

所有有限二进制问题编码可按长度、再按字典序排列。长度为 m 的编码 q，其从零开始的地址是

\[
i(q)=2^m-1+\operatorname{val}_2(q),
\]

其中空串的值约定为 0。每个有限 q 都有有限、可计算的地址；从头扫描也只需有限步到达该项，尽管可能极慢。因此“题库无限”本身不推出一次查询无法完成。可计算的地址也不保证地址上的答案能被计算得到：假定题库已经包含全部停机答案，相当于预先提供了普通算法无法生成的无限信息，不能用检索操作证明它可由算法构造。

| 要求 | 含义 | 项目中的对应边界 |
| --- | --- | --- |
| 可计算枚举 | 有程序逐步列出成员，整体可永不结束 | 已生成一批候选不等于候选已列完 |
| 有效有限穷尽 | 完整生成有限集合，并能识别结束 | 有界程序层、显式有限目录 |
| 可判定 | 对每个合法输入都有限时间给出正确判断 | 单个有限实验不能证明无限领域可判定 |
| 实际可行 | 时间、存储等成本可承受 | 试验额度、复核额度和总使用成本分别记录 |

停机问题的答案候选只有两个，仍不存在对任意程序和输入都结束的统一正确判定器。有限条求解路径也可能各自无限长。要靠有限搜索保证求解，必须有效取得不漏解的完整候选集、保证候选检查终止，并能识别穷尽及无解。把这些性质统称为“压缩”不会自动获得它们。可计算性背景见 [Turing 原论文](https://www.cs.virginia.edu/~robins/Turing_Paper_1936.pdf)。

## 可复用结构与终止依据

识别特殊性可以具体化为：识别当前问题属于哪个可复用的结构类，并找到保持答案的变换及终止依据。例如欧几里得算法：

\[
\gcd(a,b)=\gcd(b,a\bmod b),\qquad 0\le a\bmod b<b\quad(b>0).
\]

前式保持答案，后式给出严格下降的非负整数。规则覆盖无限多个整数输入，终止性来自下降量，完全不需要把全部答案先缩成有限表。本项目位栈机的 `halt` 顺序程序则由有限代码直接保证结束；`again` 在预算内只能报告 `resource_limit`，不能报告错误答案或一般的“不停机证明”。

这里有三项不同的优化：用短规则代替答案表是描述压缩；利用不变量或反例减少分支是搜索减少；保存中间结果以免重算是缓存。短程序可能运行很久，大表也可能查询很快。`DescriptionLength`、自主运行成本和[完整使用成本](performance_lifecycle.md)分别衡量，不能相互代替。

## 事实能否从现有输入推出

令 H 为声明的可能历史，a(h) 为求解器可以获得的信息，t(h) 为所需答案。精确求解器 g 存在必须满足

\[
a(h_1)=a(h_2)\ \Longrightarrow\ t(h_1)=t(h_2).
\]

证明很直接：g 对相同输入只能给出相同答案。如果条件不成立，增加搜索时间也不能让同一个输出同时满足两个不同目标。这不依赖历史是否随机，只依赖可用信息是否区分了目标差异。

在显式完整有限表内，上式也足以构造宏观答案表；这正是 `FiniteTaskAbstraction` 的判断因子化条件。对无限域，上式只保证集合意义的因子函数存在，不保证它可计算。若还要在宏观层组合执行，继续检查操作同余和可适用性，见[任务抽象](task_abstraction.md)。

例如，两个历史中第 37 次硬币分别为正、反，但提问者只提供同一个问题、没有记录。这两种历史构成可重放的成对反例。提供结果记录后可以消除该反例；程序仍不能凭空恢复未提供的记录。示例没有对真实随机性或实际历史作经验认证。

规则也不是可免费忽略的信息。固定解码规则时，N 位表有 2^N 种，长度小于 N 的二进制描述总共只有 2^N−1 种，因此不能把所有这样的表无损缩短。完整比较还要计算解码程序、模型及任务专属背景；把答案搬进解码器不能视为消除了答案信息。Kolmogorov 复杂度的定义及一般不可计算性见 [Grünwald 与 Vitányi](https://arxiv.org/html/0809.2754v2)，并不意味着本项目能计算任意对象的最短描述。

## 有限参数可以搬入程序，不能无条件删掉

经典计算模型下，若 F 可计算、θ 为固定有限比特串，可把 θ 写入程序，构造

\[
P_\theta(x)=F(\theta,x).
\]

这只是信息存放位置的改变。允许足够工作存储时，它不扩大经典可计算函数类别；删除 θ 而不提供重建它所需的输入或规则，则不能保证保留行为。训练方法也不能单独重建任意训练数据决定的参数。若允许无限精度常量装入不可计算序列，并精确读取任意位，就改变了信息模型，不属于上述有限参数论证。

`computation_search.inline_initial_bits(program, *, width)` 在现有机器中落实这个有限构造：按原栈顺序，把 `initial` 中的 0/1 变成代码前缀 `zero/one`，结果初态为空。每次内部重置后也先重建原栈。对 `halt` 程序，前缀执行完时的栈与原初态一致，后续指令相同，因此输出相同；两种 `again` 程序均持续重置而不输出。

原程序有 L 条指令、D 个初始位时：

\[
C_{\mathrm{原}}=2L+D+1,\qquad
C_{\mathrm{内联}}=2(L+D)+1=C_{\mathrm{原}}+D.
\]

两者装载成本均为 L+D；新增成本来自执行 D 条字面量指令。此为当前机器的单位成本，并非比特编码长度或普遍编译下界。同预算下，原程序可完成而内联程序超限；不能要求二者的有界回执相同。输出等价不保留原成本、原最优性或原证书结论，须对结果程序重新计费复核。这个构造不改变语言、枚举或证书格式，也没有去掉运行时工作栈。

示例：`initial=(1,)`、`input:0, xor, halt` 实现非运算，成本 8；内联后 `one, input:0, xor, halt` 成本 9。若该位为 0，则实现恒等函数；空初态代码中的 `zero/one` 仍保留了这个差异。“哈佛架构”指指令与数据的存储/访问组织，与参数固定是不同维度；本文使用“参数固化”与“初态内联”描述此处操作。

## 对双向建模的约束

宏观目标筛选微观候选时，先检查提供的信息能否区分目标答案；微观反例再反向指出宏观输入丢失了哪项必要差异。可选择补充观测、保留参数或缩小任务范围。只有找到可重建该信息的规则及充分输入，才可以把事实存储替换为计算。

压缩与智能的关系可以作为研究假设；[Rissanen 的最小描述长度工作](https://research.ibm.com/publications/modeling-by-shortest-data-description)讨论用描述长度选择模型，[Hutter 的研究动机](https://www.hutter1.net/prize/hfaq.htm)联系压缩和智能。这些方向不提供通用最佳压缩发现器，也不代替本项目的完整目标验收、终止依据和资源复核。

可检验的工作主张是：对具有统一可执行且逐输入终止规则、并提供充分事实信息的领域，系统可以不逐题保存答案。发现规则、证明适用、执行求解、检查结果分别承担成本。有限样例只能验收声明的有限域，不能把 XOR 示例的真值表检查推广为无限领域证明。

```bash
PYTHONPATH=src python3 examples/compression_and_information.py
PYTHONPATH=src python3 -m unittest discover -s tests -p test_compression_information.py -v
```

示例用现有任务抽象给出缺失事实的反例及补充记录后的因子表，并展示不查询目标表的 XOR 程序和两种参数的内联成本。回归覆盖小规模完整程序层、栈顺序、全部小预算截点、参数差异、声明拒绝和重新复核后的非最优性；不据此主张任意编译器正确或无限领域完备。
